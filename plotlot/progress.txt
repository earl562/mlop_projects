## Codebase Patterns

Curated, reusable learnings consolidated from the log below (snarktank pattern).
General + reusable only; story-specific details stay in the dated log entries.

- **Never `git stash`** (AGENTS.md + Slice 0.2). Use a preservation commit or `git checkout -- <file>`.
- **After `git commit --amend`**, re-capture the hash: `FINAL_HASH=$(git log -1 --format=%H)`. Pre-amend hashes are stale.
- **ArcGIS layer URLs are the layer resource** (`.../FeatureServer/0`), not the query endpoint. `_query_nearby_sales` must append `/query`. Registered `SalesSource.layer_url` values do NOT end in `/query`.
- **ArcGIS metadata listings diverge from live schemas.** Before trusting registered field names, reconcile against the live `/<layer>?f=json`. Slice 1.2 shipped `PARCELNO`/`LOTSQFT` that didn't exist on the live Palm Beach layer.
- **`_find_field` uses substring fallback** (added Slice 1.2). DB-qualified (`SQLGIS02.dbo.BCPA_SALES.SALE_AMOUNT`) and suffixed (`PRICE_1`, `DOS_1`) names match via contains, not just exact.
- **`_PRICE_FIELDS` includes `SALE_AMOUNT`**; **`_DATE_FIELDS` includes `DOS`, `DATEOFSALE`** (added Slice 1.2 for Broward + Miami-Dade).
- **`safe_float` strips `$` and commas**; `_parse_sale_date` handles epoch ms. Broward's `"$1,850,000"` string and epoch-ms dates parse correctly.
- **Live integration tests** live in `tests/integration/` and are gated by `PLOTLOT_LIVE_TESTS=1`. The deterministic gate (`make verify-local`) skips them. Run explicitly before any "feature works" claim.
- **CLAIM-WITHOUT-EVIDENCE GUARD:** unit tests passing ≠ feature works. Before claiming a feature works for a real input, run it live + assert sane output + write an integration test pinning it. (Skill v2.1 step 6.)
- **`domain/` layer convention:** frozen dataclasses with `slots=True` + `__post_init__` invariants (see `dimensional_standard.py`, `claims.py`). A frozen dataclass CANNOT be mutated even via `object.__new__`, so predicate-form invariants (e.g. `source_boundary_ok()`) exist to validate *deserialized* rows that bypassed construction — test them with a lightweight stub dataclass carrying matching attrs, not by mutating a Claim.
- **Source boundary (Slice 2.1):** `zoning.*` / `parcel.*` claims must be `origin=local_authority` (the Rehab Valuator corpus is NOT a zoning oracle). `cost.*` / `cap_rate` / `financing.*` / `rent.*` must never be `kind=verified_fact`. Both raise `SourceBoundaryViolation` at construction. Downstream `steps.py`/`guardrails.py` build rules *over* `Claim`, not new types. The canonical namespace sets are the PUBLIC module constants `LOCAL_AUTHORITY_NAMESPACES` / `ASSUMPTION_NAMESPACES` in `claims.py` (import them — never re-declare, to avoid drift).
- **Guardrails (Slice 2.3) vs constructor invariants:** rules 1–3 of `domain/guardrails.py` overlap the `Claim.__post_init__` invariants, but the guardrails run over a *ClaimLog* (loaded from storage / aggregated across runs / tool-fed) whose rows BYPASS construction. So the guardrails are the SET-level re-validation (report-validator foundation, spec acceptance #7). Test rule-violating log rows with a STUB dataclass (matching attrs + `namespace` property, no `__post_init__`) — a frozen `Claim` cannot be constructed in a violating state. A contradiction is an ESCALATION (`requires_human_review=True`), not an integrity failure.
- **Type relocation across layers (Slice 2.4):** when moving shared types to a lower layer, prefer re-export-by-identity (`from lower import X`) in the old location over mass-editing N consumer files. Identity is cheaply testable (`obj is obj`) and the shim lets new code migrate incrementally. Move a type WITH its dependency closure (e.g. `EvidenceItem` pulls `EvidenceCitation`/`SourceType`), else you force an up-import cycle or a divergent re-declaration. To assert "module X doesn't import from module Y" in a test, walk the parsed AST `Import`/`ImportFrom` nodes — substring-matching the source catches docstring mentions (false positives).
- **Mocking SQLAlchemy's `pg_insert` in unit tests (Slice 3.1):** the builder chain is `pg_insert(Model) -> .values(rows) -> .on_conflict_do_update(constraint=..., set_=...) -> stmt`. Use `MagicMock` for the stmt chain (it's sync), `AsyncMock` only for the session. `mock_insert.call_args[0][0]` is the MODEL; the rows are at `mock_stmt.values.call_args[0][0]`; the conflict call is at `mock_stmt.values.return_value.on_conflict_do_update.call_args` — three `.return_value` levels deep.
- **Structural vs embedding unit (Slice 3.1):** `OrdinanceChunk` is the embedding/retrieval unit; `OrdinanceSection` is the structural unit (one row per municode node, keyed (municipality, node_id)) carrying path/section_type/cross_refs/referenced_by. A section's chunks all share its path/cross_refs/section_type. The reverse-index `referenced_by` is owned by the Slice 3.5 backfill — ingestion upserts must OMIT it from `set_` so a refresh never clobbers the backfill-built reverse index. Table is provisioned by `init_db`→`Base.metadata.create_all`; migrations are belt-and-suspenders (idempotent) for the operator-managed alembic path.
- **Recovering a mixed/broken working tree across story boundaries (WIRE-1.1b):** when a prior iteration left uncommitted changes spanning TWO stories (the target + an incomplete neighbor), do NOT commit the lot — that ships untested scope and conflates one-story-per-commit. `git stash` is forbidden (AGENTS.md). The sanctioned recovery is the **preservation-commit pattern**: `git checkout -b wip/snapshot-...`, `git add <explicit paths>`, commit (clearly marked wip/broken, NOT for merge), `git checkout dev`, then `git checkout wip/snapshot-... -- <only the in-scope files>` to selectively restore just the target story's files. `git checkout <tree-ish> -- <path>` is a SAFE restore-from-tree (not the forbidden `git checkout .`/`git checkout -- <file>` discard form). Remove untracked neighbor artifacts (e.g. an orphan migration) with `rm <file>` (preserved on the wip branch). Verify the committed dev version of a dependency exists before relying on it (e.g. `DistrictDimensionalStandard.to_numeric_zoning_params()` was already on dev from Slice 1.1 — the WIRE-1.1b calculator wiring needed nothing new in `dimensional_standard.py`).
- **Provenance labeling on `DensityAnalysis` (WIRE-1.1b):** `DensityAnalysis.origin` (`"local_authority"` | `"unknown"`) mirrors the `Claim` origin taxonomy and is the seam where the typed `DistrictDimensionalStandard` (verified-fact, ingestion-time) replaces LLM-extracted `NumericZoningParams` (assumption-grade). `calculate_max_units` accepts either type; passing a `DistrictDimensionalStandard` forces `density_verified=min_lot_area_verified=True` (the typed row IS the authority) AND labels the result `local_authority`. A caller that converts via `.to_numeric_zoning_params()` itself passes `origin="local_authority"` to preserve the label. Provenance propagates to ALL return paths (no_lot_data, insufficient_data, normal) — every return site sets it.

- The 5 rules:
  1. LOCAL_AUTHORITY_ORIGIN — zoning.*/parcel.* must be origin=local_authority.
  2. ASSUMPTION_NAMESPACE — cost.*/cap_rate/financing.*/rent.* must NOT be

  4. MATERIAL_EVIDENCE — material claims (verified_fact OR recommendation/

  SET-level re-validation (the report validator foundation, spec acceptance #7:
  "report fails on missing evidence_ids / blurred boundaries / hidden
  contradictions"). The contradiction rule is intentionally NOT an integrity
  failure — a consistent log can still need adjudication.
- DRIFT PREVENTION: promoted claims.py's `_LOCAL_AUTHORITY_NAMESPACES` /
  `_ASSUMPTION_NAMESPACES` to public `LOCAL_AUTHORITY_NAMESPACES` /
  `ASSUMPTION_NAMESPACES` and imported them in guardrails.py — single source
  of truth for the boundary (the Codebase Patterns warn about divergent
  registries; this avoids a second copy of the namespace sets). Exported from
  domain/__init__.py.
- MATERIAL definition: `is_material(c)` = kind==verified_fact OR namespace in
  {recommendation, metrics, value}. Pure assumptions (user cost, market cap
  rate) are EXEMPT — they're already amber-rendered + provenance-tracked via
  source_url/origin, not evidence rows. Tested explicitly.
